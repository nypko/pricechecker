# Page Tops That Say What DoorPrice Is: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The first screen of the home page and of every phone page says what DoorPrice is, names the stores with their ratings, shows how fresh prices are, shows phone photos and key specs, and gives each version box a network line for the visitor's country; "every hour" becomes "several times a day".

**Architecture:** Static Jinja site rebuilt by the scheduled check. Every price block exists twice, a Jinja macro (`templates/_d/blocks.html`) and a JS twin (`static/js/blocks.js`) kept equal by `tests/test_blocks.py`; carrier logic is mirrored the same way (`pricechecker/carriers.py` ↔ `static/js/carriers.js`). New page-top pieces live in `templates/_d/top.html`. Photos are processed once by a local tool into `static/phones/` and served from the site.

**Tech Stack:** Python 3.12, Jinja2, PyYAML, Pillow 13 (already in requirements.txt), vanilla ES modules, node for JS tests, pytest.

**Spec:** `docs/superpowers/specs/2026-11-11-trust-top-design.md` (approved 2026-11-11). Mockups: `.superpowers/brainstorm/19954-1794343935/content/` (`home-top-v2.html` B1, `phone-top.html` P1, `network-check.html` N2).

## Review Focus

1. Settings without a country (EU average, Rest of the world) or with a province (Canada): place reads "the EU" / "your country" / "Canada" or the province, the network line asks to choose a country, and "Canada" with any province uses the CA carrier file (Task 2, Task 5 tests).
2. Spec values that list versions ("8,000 mAh / 7,150 mAh (EU)", "7,200 mAh (China) / 7,100 mAh (Global) / 6,270 mAh (EU)") and values without digits: the row shows "up to 8,000 mAh" or the text as is, never a crash (Task 8 tests).
3. A store whose latest check failed, and Trading Shenzhen's EU warehouse: one store counted once, "5 of 6 stores checked" (Task 8 tests).
4. Odd photo sources: palette PNG with transparency (Xiaomi's are), JPEG on white, an HTML error page instead of an image, a tiny image: the tool processes or refuses each with a message and goes on with the next phone (Task 7 tests).
5. A visitor's clock behind the build time, or an unreadable `datetime`: "just now", or the server text left as it is (Task 2 tests).

### Task 5: The network line's wording (`box_line` / `boxLine`)

**Interfaces:**
- Consumes: `_judge(phone, network, table) -> (verdict, first)`, `_names`, `_label` (existing).
- Produces: `box_line(phone: dict | None, country_doc: dict | None, table: dict, country_name: str | None) -> dict` → `{"tone": "good" | "bad" | "neutral" | "muted" | "pick", "text": str}`; JS `boxLine(phone, countryDoc, table, countryName)` with the same output.

Rules (spec §7 + Global Constraints clarifications): phone `None` or both lists `None` → muted "Bands not published for this version"; no `country_doc` → pick "Networks: choose your country"; else judge every network, worst kind by `SEVERITY = ("risk", "4g", "minor", "unknown", "nogaps", "full")`, the first network of that kind gives {reason} (its `first`) and {use} (`use` of its missing band whose `_label` equals `first`, text after the first ": "); group = networks of that kind; names = `_names(group names)`; {where} = `in {country}` if the group is every network else `on {names}`.

| Worst | Text | Tone |
|---|---|---|
| full | 1 network: `✓ works on {name}`; 2: `✓ works on both networks in {country}`; n ≥ 3: `✓ works on all {n} networks in {country}` | good |
| nogaps | `✓ no gaps found in {country}` | good |
| risk | `{Reason} {where}: weaker {use}` | bad |
| 4g | `No 5G {where}` | neutral |
| minor | every network: `Works in {country}; {reason} ({use})`; else `Works in {country}; {reason} on {names} ({use})` | neutral |
| unknown | `Bands not known {where}` | muted |
